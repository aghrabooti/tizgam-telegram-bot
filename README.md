# 🤖 ربات تلگرام موسسه تیزهوشان تیزگام

ربات رسمی موسسه تیزهوشان تیزگام برای معرفی موسسه، نمایش ویدیوهای قبولی و
رضایت، محصولات پایه ششم و نهم، نمونه کلاس‌ها و آزمون‌ها، پشتیبانی و خرید
تیزپک — با منوی کاملاً Inline و ناوبری چندمرحله‌ای.

- **زبان/پلتفرم:** Python 3.10+
- **کتابخانه:** [python-telegram-bot](https://python-telegram-bot.org) v22 (async)
- **پیکربندی:** تمام محتوا در یک فایل متمرکز (`bot/config/content.py`)

---

## ✨ امکانات

| # | بخش | توضیح |
|---|------|-------|
| ۱ | درباره موسسه | متن معرفی + لینک/رسانه‌ی قابل تنظیم |
| ۲ | ویدیو قبولی‌های تیزگام | لیست ویدیوها (دکمه‌های لینک‌دار از کانفیگ) |
| ۳ | ویدیو رضایت‌های تیزپک | لیست ویدیوهای رضایت‌مندی |
| ۴ | محصولات پایه ششم و نهم | پایه ← لیست محصولات ← جزئیات + لینک سفارش |
| ۵ | پشتیبانی | تماس تلفنی (شماره + ساعات) / گفت‌وگو در تلگرام |
| ۶ | خرید تیزپک | توضیح محصول + قیمت + لینک خرید |
| ۷ | نمونه کلاس‌ها | پایه ← درس ← لینک جلسه‌ی نمونه در آپارات |
| ۸ | نمونه آزمون | پایه ← لیست آزمون‌ها ← لینک مشاهده/دانلود |
| ۹ | رسانه‌های تیزگام | تلگرام / اینستاگرام / بله / روبیکا / ایتا / سایت |
| 🛠 | **پنل مدیریت** | `/admin` → آمار کامل + ویرایش محتوا از خود تلگرام |

**رفتار UX:**
- همه‌ی منوها Inline Keyboard هستند و هر کلیک، **همان پیام را ویرایش می‌کند**
  (`editMessageText`) — بدون شلوغ کردن چت کاربر.
- هر صفحه دکمه‌ی بازگشت دارد؛ صفحه‌های سطح ۲ به بعد ردیف
  `[🔙 بازگشت] [🏠 منوی اصلی]` و صفحه‌های سطح ۱ دکمه‌ی
  «🔙 بازگشت به منوی اصلی» دارند.
- `/start` در هر مرحله‌ای → reset کامل و نمایش منوی اصلی.
- ناوبری **state-less** است (درخت ثابت؛ هر صفحه والدش را می‌شناسد)؛ بنابراین
  بازگشت همیشه دقیقاً یک مرحله عقب است و هیچ state خرابی وجود ندارد.
- دکمه‌های منقضی (مثلاً بعد از تغییر کانفیگ) با یک هشدار، کاربر را به منوی
  اصلی برمی‌گردانند.
- **دکمه‌های رنگی (Bot API 9.4+):** دکمه‌های اقدام/لینک (تماشا در آپارات، ثبت
  سفارش، گفت‌وگو با پشتیبانی و...) سبز (`success`) و دکمه‌ی خطر «بله، پاک
  شود» قرمز (`danger`) نمایش داده می‌شوند. کلاینت‌های قدیمی تلگرام، این
  دکمه‌ها را با رنگ پیش‌فرض آبی می‌بینند.

## 🚀 راه‌اندازی

```bash
# ۱) نصب وابستگی‌ها
pip install -r requirements.txt

# ۲) تنظیم توکن
cp .env.example .env
# سپس BOT_TOKEN را از @BotFather در .env قرار دهید

# ۳) اجرا
python -m bot
```

## 🧪 تست‌ها

```bash
pip install -r requirements-dev.txt
pytest                # ۲۳ تست یکپارچه؛ تمام flowها بدون نیاز به توکن/شبکه
python scripts/demo_flows.py   # دموی خوانا: شبیه‌سازی کامل کاربر در ترمینال
```

تست‌ها اپلیکیشن واقعی را با یک Bot ساختگی (mock) اجرا می‌کنند و مسیریابی
کامل ربات را بررسی می‌کنند: `/start`، هر ۹ بخش، بازگشت‌ها و منوی اصلی،
دکمه‌های منقضی، callback ناشناخته و پیام متنی نامفهوم.

## 🏗 معماری

```
bot/
├── main.py               # ساخت اپلیکیشن و run_polling
├── __main__.py           # python -m bot
├── constants.py          # 🔑 قرارداد callback dataها + patternهای regex (تنها منبع حقیقت)
├── config/
│   ├── settings.py       # تنظیمات اجرا (BOT_TOKEN، لاگ) — از .env
│   └── content.py        # 🎛 تمام محتوای قابل‌تنظیم (متن/لینک/محصول/درس/رسانه)
├── handlers/             # فقط منطق «واکنش به رویداد» — بدون متن و لینک
│   ├── start.py          # /start و منوی اصلی
│   ├── about.py          # درباره موسسه
│   ├── videos.py         # قبولی‌ها / رضایت‌ها
│   ├── products.py       # محصولات: پایه ← محصول ← سفارش
│   ├── support.py        # پشتیبانی: تماس / تلگرام
│   ├── purchase.py       # خرید تیزپک
│   ├── classes.py        # نمونه کلاس: پایه ← درس ← آپارات
│   ├── exams.py          # نمونه آزمون: پایه ← آزمون ← لینک
│   ├── media.py          # رسانه‌های اجتماعی
│   └── errors.py         # error handler، callback ناشناخته، متن نامفهوم
├── keyboards/
│   ├── common.py         # سازنده‌های مشترک (ردیف ناوبری، انتخاب پایه)
│   └── menus.py          # کیبورد اختصاصی هر صفحه
├── services/
│   ├── navigation.py     # رندر صفحه‌ها (edit همان پیام + fallbackها)
│   ├── database.py       # SQLite (آمار + مقادیر ویرایش‌شده‌ی مدیر)
│   ├── analytics.py      # ثبت و گزارش رویدادها (start / نمایش صفحه‌ها)
│   └── content_manager.py # ویرایش پویای محتوا از پنل مدیریت
└── utils/
    └── text.py           # escape امن HTML و ابزارهای متنی

tests/                    # تست یکپارچه‌ی flowها (pytest + mock bot)
scripts/demo_flows.py     # دموی تعاملی بدون توکن
```

**تفکیک مسئولیت‌ها:** هندلرها فقط هماهنگی می‌کنند؛ متن‌ها/لینک‌ها فقط در
`content.py`؛ callbackها فقط در `constants.py`؛ ساخت کیبورد فقط در
`keyboards/`؛ رفتار رندر/ناوبری فقط در `services/navigation.py`.

### طرح callback data

```
main                        منوی اصلی
about | vid:acc | vid:sat   بخش‌های تک‌مرحله‌ای
buy | media
sup | sup:call | sup:tg     پشتیبانی
prod            [:g:{grade}[:{product}]]
cls             [:g:{grade}[:{subject}]]
exm             [:g:{grade}[:{exam}]]
```

الگوهای regex فقط «شکل» داده را اعتبارسنجی می‌کنند؛ اعتبار مقادیر (وجود
پایه/درس/محصول) در هندلرها با کانفیگ چک می‌شود. به همین دلیل **افزودن پایه،
درس، محصول یا آزمون جدید هیچ تغییری در کد هندلرها لازم ندارد.**

## 🎛 راهنمای تغییر محتوا (مخصوص مدیر پروژه)

همه‌چیز در **`bot/config/content.py`** است. ⚠️ مقادیر فعلی لینک/شماره
**placeholder** هستند و باید قبل از استقرار جایگزین شوند.

<details>
<summary><b>تغییر لینک آپارات یک درس</b></summary>

```python
# bot/config/content.py → GRADES → پایه مورد نظر → subjects
Subject("math", "ریاضی", "➗", "https://www.aparat.com/v/REAL_VIDEO_ID"),
```
</details>

<details>
<summary><b>افزودن درس جدید به پایه (مثلاً هندسه پایه نهم)</b></summary>

فقط یک `Subject` به تاپل `subjects` همان پایه اضافه کنید؛ دکمه‌ی آن به‌صورت
خودکار ساخته می‌شود.
</details>

<details>
<summary><b>افزودن پایه جدید (مثلاً هفتم)</b></summary>

یک `Grade(id="7", ...)` به `GRADES` اضافه کنید. برای محصولات/آزمون‌های آن
پایه هم کلید `"7"` را در `PRODUCTS_BY_GRADE` / `EXAMS_BY_GRADE` اضافه کنید.
</details>

<details>
<summary><b>افزودن محصول جدید</b></summary>

یک `Product(...)` به تاپل پایه‌ی مربوطه در `PRODUCTS_BY_GRADE` اضافه کنید.
</details>

<details>
<summary><b>تغییر شماره پشتیبانی / لینک تلگرام پشتیبانی</b></summary>

شیء `SUPPORT` را ویرایش کنید (`call_text` و `telegram_url`).
</details>

<details>
<summary><b>تغییر لینک خرید تیزپک / قیمت / متن</b></summary>

بخش `PURCHASE_SECTION` را ویرایش کنید. تا زمان اتصال درگاه پرداخت، دکمه‌ی
خرید به `order_url` (سایت یا تلگرام فروش) هدایت می‌شود.
</details>

<details>
<summary><b>تغییر لینک شبکه‌های اجتماعی</b></summary>

آیتم‌های `MEDIA_SECTION.items` (تلگرام/اینستاگرام/بله/روبیکا/ایتا/سایت).
</details>

<details>
<summary><b>افزودن عکس/ویدیو به یک بخش محتوایی</b></summary>

هر `ContentSection` علاوه بر `text` و `items`، فیلد اختیاری `photo_url` و
`video_url` دارد؛ اگر تنظیم شوند، رسانه بعد از صفحه برای کاربر ارسال می‌شود.
</details>
